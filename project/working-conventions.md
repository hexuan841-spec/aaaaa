# 工作方式与交付约定

- 内容具体、简洁、让不了解的人也能看懂；用户说先讨论时，不将未确认方向写成最终规则。
- 用户指定最新截图或文件时以其为准，修改前读取当前文件；局部修改不顺带重排、改文案或换图。
- 功能方案先说明目标和对象，再写操作、状态、字段、条件与结果；用具体例子说明复杂规则。用户只要一小段时直接提供短文本。
- 图片仅在对应的设计状态和来源明确时使用；原图参考、生成概念图、确认稿要区分。要改图时根据用户指定的版本修改，不声称无验证的一比一复刻。
- 表格中的需求简述突出对象和核心改动；程序细节另外写清字段、可选值、显示条件、联动和边界。
- 生成文件、自动检查、视觉检查及原生软件核验分别报告；历史工作记录不能证明当前文件和产品状态。
- 1910 年代或薇诺娜制作设定按具体美术任务决定，不能一律套用；单面、动画、碰撞、尺寸也按节点实际需求确认。
