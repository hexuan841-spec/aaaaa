# 已确认存在的 UGC 预设

进行新预设发散、功能补齐、表格描述或示意图设计前，先与本清单查重。以下能力视为已经存在，除非用户明确说正在替换或重做。

## 信号与基础逻辑

- 逻辑开关：支持是非、与、或、同或、异或等逻辑运算。
- 切换开关：触发后切换开关状态。
- 感应开关：可通过范围踩入、离开范围或接收信号触发，并可发送信号。
- 计数器：接收信号后改变计数，到达目标数发送信号。
- 计时器：接收信号后开始、暂停或重置计时，到达目标时间发送信号。
- 接收信号-关卡结束：收到指定信号后结束关卡。
- 接收信号-关卡失败：收到指定失败信号后，以失败结果结束关卡。界面一比一沿用接收信号-关卡结束，只改标题与结算语义。

## 场景与交互

- 物理门：接收信号控制开启或关闭，并在状态变化时发送对应信号。
- 接收信号-召唤预设：收到信号后召唤配置预设，召唤对象不限于生物。
- 提交道具门：玩家提交指定道具后开门。
- 道具箱：预先配置箱内放置的指定物品。
- 传送门：两个传送门对应配置，选择目标后传送。
- 横幅：收到信号后，在画面顶部显示大型横幅气泡及配置文字。

## 陷阱与战斗

- 地刺陷阱：接收信号后激活或关闭，支持伤害配置。
- 喷火陷阱：接收信号后激活或关闭，支持伤害配置。
- 检测怪物死亡：配置指定目标生物，目标死亡后发送信号。
- 怪物生成器：用于配置刷怪位置、召唤内容、召唤控制和循环召唤。当前正在优化为支持刷怪方式、位置坐标、召唤大组和组内完成信号。

## 数据与条件

- 值：读取并提供其他节点使用的数据。已经做过界面优化讨论与效果图设计。
- 赋值：修改指定目标的数据或状态。已经做过界面优化讨论与效果图设计。
- 判断条件：比较参数并得到是否满足条件的结果。已经做过界面优化讨论与效果图设计。
- 条件分支：根据一个或多个条件结果选择后续执行逻辑。已经做过界面优化讨论与效果图设计。
- 运算预设：已存在。具体支持的运算类型和字段以用户提供的当前界面为准。

## 经济与随机

- 商品 / 商品台：已存在。具体字段以当前界面和用户说明为准。
- 随机掉落：已存在。具体随机池、权重和数量规则以当前界面为准。

## 已知限制

- 当前不能读取玩家状态、玩家背包数量或其他玩家信息；不要把依赖这些读取能力的方案描述成现有功能。
- 可以读取怪物相关信息，生命值只是可读写属性之一；具体属性以实际操作类型列表为准。
- 召唤预设不限于生物，可以召唤物品或其他可配置预设。
- 新功能建议应优先补足现有预设无法简洁组合出的能力，不要重复包装已有死亡、区域、计时、计数和信号功能。
